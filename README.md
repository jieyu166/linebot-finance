# linebot-finance

LINE Bot + Google Apps Script + OpenAI 個人記帳系統

## 功能

- **文字記帳**：透過 LINE 傳送「午餐80」等自然語言，AI 自動解析分類、品項、金額
- **固定格式**：支援「飲食 午餐便當 80」指定分類格式
- **銀行帳單匯入**：貼上銀行帳單文字或傳送 PDF，批次匯入交易紀錄
- **帳戶餘額查詢**：在「帳戶管理」工作表填入初始餘額後，傳送「餘額」即可查詢各帳戶當前餘額
- **動態分類**：在 Google 試算表直接新增分類，不需修改程式碼
- **多幣別**：支援 TWD、USD、JPY 等幣別辨識

## 架構

```

    │
    ▼ (Webhook POST)
Google Apps Script (Web App)
    ├── OpenAI API (gpt-4o-mini) — 解析記帳訊息
    ├── Google Sheets — 儲存交易紀錄、帳戶主檔
```

## 工作表結構

### 交易紀錄（12 欄）

| 日期 | 金融機構 | 帳戶名稱 | 類型 | 分類 | 品項 | 明細描述 | 幣別 | 金額 | 原始訊息 | ID | 轉帳ID |
|------|---------|---------|------|------|------|---------|------|------|---------|----|----|

- **ID**（K 欄）：每列寫入時自動產生 UUID，供程式定位列（不依賴列號）。
- **轉帳ID**（L 欄）：配對成功的兩列（繳信用卡↔卡費入帳、轉帳兩端、ATM 提款、交割戶入帳）共用同一組 UUID；空白表示尚未配對。

### 帳戶管理（10 欄）

| 帳戶名稱 | 金融機構 | 幣別 | 初始餘額 | 初始日期 | 備註 | 是否啟用 | 帳戶類型 | 扣款帳戶 | 帳號識別 |
|---------|---------|------|---------|---------|------|---------|---------|---------|---------|

- **帳戶類型**：`現金`／`銀行`／`信用卡`／`證券`。空白時：名稱含「現金」視為現金，其餘視為銀行。
- **扣款帳戶**：信用卡帳戶填其自動扣繳的銀行帳戶名稱；證券帳戶填常用匯入來源帳戶，自動配對優先使用此欄判斷對方帳戶。
- **帳號識別**：該帳戶在對帳單上可見的帳號片段，可用逗號分隔多個子帳號（如玉山 `0015977,0381979`）；綜合對帳單含多帳號時，後端以此把各帳號區塊的交易指到正確帳戶。

初始餘額與初始日期留空由使用者填入；信用卡帳戶請填「上期未繳金額的負數」與「該期結帳日」。已存在的「帳戶管理」工作表再次執行 `initializeSheets()` 只會呼叫 `upsertDefaultAccounts()` 補齊 H/I/J 欄標題與缺少的帳戶列，不覆蓋既有資料。

- **帳戶名稱**是交易紀錄 C 欄的比對鍵，OpenAI 解析時會從此清單選擇最接近的名稱。
- **初始日期**當天（含）以前的交易不計入，從次日起累計。留空則計入全部交易。
- 分類為「繳信用卡」的交易**計入**餘額（銀行帳戶端扣款、信用卡帳戶端因自動配對加回），不再排除；信用卡帳戶的當前餘額為負數即代表未繳金額。
- 交易列對應帳戶的規則（依序）：C 欄 = 帳戶名稱；C 欄 = 金融機構名稱；C 欄空白且 B 欄 = 金融機構（舊資料）；C 欄與 B 欄皆空白視為現金。比對忽略空白與大小寫。
- 金額欄可為數字或含千分位的字串（如 `1,234`），支出取絕對值。
- 餘額算不對時，在 Apps Script 編輯器執行 `debugAccountBalance('帳戶名稱')`，Logger 會列出每筆交易被排除的原因統計。

## 餘額查詢指令

| 傳送內容 | 回覆 |
|---------|------|
| `餘額`、`查餘額`、`所有餘額`、`帳戶餘額` | 所有啟用帳戶的當前餘額一覽，分「【資產】」（現金／銀行／證券）與「【信用卡】」兩區 |
| `永豐大戶餘額` 或 `餘額 永豐大戶` | 單一帳戶：初始餘額、交易調整（筆數）、當前餘額 |
| `帳戶清單`、`帳戶列表` | 所有啟用帳戶名稱與幣別 |

信用卡帳戶在【信用卡】區顯示為「未繳 $X」（X 為目前餘額絕對值）；其餘帳戶顯示原始餘額。

餘額 = 初始餘額 + 收入 − 支出，每次查詢即時計算，不在工作表存快取。

## 匯入行為

- **帳單類型判斷**：OpenAI 先判斷整份帳單是「信用卡」「銀行帳戶」或「證券」（`statementType`），後端據此強制每筆交易的 `account` 對應到正確類型的帳戶。
- **帳號分流**：銀行帳戶明細每筆輸出所在段落的 `accountNumber`；後端以帳戶管理 J 欄「帳號識別」做前綴比對決定實際帳戶，對不到的帳號區塊整塊跳過，回覆列出「未對應帳號」。
- **去重**：`dedupeAgainstSheet()` 比對同帳戶、同金額、同類型、日期 ±2 天內的既有匯入列（僅比對 PDF匯入／文字匯入／自動配對來源），避免證券對帳單與銀行明細重複記帳；證券對帳單的具體股名會回填覆蓋既有的概括品項（如「定期買股」）。
- **自動配對**：寫入「繳信用卡」「轉帳」分類的列後自動嘗試找出對方帳戶（信用卡帳戶的「卡費入帳」、轉帳對方帳戶、ATM 提款轉「現金」、證券交割戶「交割戶入帳」），配對成功的兩列共用同一組轉帳ID；多個候選或無法判斷時列在回覆訊息供使用者到 App 手動連結。
- **回覆摘要欄位**：匯入完成訊息包含「帳單類型」「共匯入 N 筆交易」「支出／收入 筆數與合計」「跳過與既有紀錄重複 N 筆」「已自動配對 N 筆」「未對應帳號」等欄位，視情況出現。

## 分類

**支出（21 項）**：飲食、服飾、家庭、交通、學習、休閒、購物、醫療、其他、保險、手續費、稅金、工作、父母、老婆、買房、紅包、投資、轉帳、貸款、繳信用卡

**收入（10 項）**：薪資、利息、兼職、獎金、回饋、投資獲利、股利、家人給、保險、其他

## 設定步驟

1. 建立 Google 試算表
2. 建立 LINE Official Account + Messaging API Channel
3. 取得 OpenAI API Key
4. 從試算表「擴充功能 → Apps Script」開啟編輯器
5. 建立 7 個 .gs 檔案（含 `TransferService.gs`），貼入 `src/` 下的程式碼
6. 啟用 Drive API 進階服務
7. 設定 Script Properties（OPENAI_API_KEY、LINE_CHANNEL_SECRET、LINE_CHANNEL_ACCESS_TOKEN、SHEET_ID）
8. 執行 `initializeSheets()` 建立工作表結構（已存在的工作表不會被覆蓋）
9. 在「帳戶管理」工作表填入各帳戶的初始餘額與初始日期
10. 部署為 Web App（存取權限：所有人）
11. 在 LINE Developers 設定 Webhook URL

## 升級既有試算表

已在使用舊版（7 欄帳戶管理、無轉帳配對）的使用者，依序執行：

```
1. 貼上最新 src/*.gs（含新檔 TransferService.gs，共 7 個檔案）
2. 執行 initializeSheets()（補標題、預算表、收入分類「轉帳」、缺少的帳戶）
3. 執行 backfillTransactionIds()
4. 在「帳戶管理」填帳戶類型、扣款帳戶、帳號識別、初始餘額（信用卡填上期未繳金額的負數，初始日期填該期結帳日）
5. 舊資料搬移：先 migrateCreditCardRows('一銀','一銀信用卡','','',true) 預覽，確認後改 dryRun=false 執行；國泰同理；永豐信用卡依月份區間指定
6. 執行 pairExistingCreditCardPayments(false) 補配對既有繳卡費
7. 在 LINE 傳「餘額」核對
```
